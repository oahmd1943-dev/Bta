# بَطّة — جرد وإدارة المحل 🦆

تطبيق عربي متكامل (RTL) لإدارة محل تجاري صغير: **جرد + مبيعات + ديون + ميزانية + تصدير Excel**، يعمل محلياً بالكامل دون إنترنت ودون إرسال أي بيانات إلى أي خادم.

> **الهوية:** ي.أ.م — **Y.A.M** · الإصدار **1.0.0** · جميع الحقوق محفوظة © 2026

---

## 1. نظرة سريعة

| العنصر | التفاصيل |
| --- | --- |
| واجهة عربية كاملة | RTL، خط Cairo، تصميم Material-inspired حديث |
| التبويبات | الجرد · المعاملات · الديون · الميزانية |
| سعر الصرف | إدخال يدوي + زر تحديث يعيد حساب كل الأسعار في التطبيق دفعة واحدة |

| المظهر | وضع نهاري وليلي، شاشة بداية بالشعار، انتقالات خفيفة |
| اللغة | عربية 100% |

## 2. التقنية والملفات

- **React 19 + TypeScript + Vite 7 + Tailwind CSS 4**
- **lucide-react** للأيقونات.
- **بدون قاعدة بيانات خارجية**؛ كل شيء محلي.
- **Service Worker** (`public/sw.js`) يخزّن هيكل التطبيق للعمل دون إنترنت بعد أول زيارة لنسخة الإنتاج.
- ملف Excel يُبنى داخلياً بصيغة XML SpreadsheetML متوافقة مع Excel و Google Sheets و«ملفات» على أندرويد، دون أي مكتبة ثقيلة.

```
├─ index.html                 # RTL + الخطوط + manifest
├─ package.json               # المتطلبات
├─ vite.config.ts             # إعداد Vite (لا تعدّله إلا عند الحاجة)
├─ tsconfig.json
├─ public/                    # الشعار والأيقونات
├─ README.md                  # هذا الملف
└─ src/
   ├─ App.tsx                 # الهيكل، شاشة البداية، التبويبات، التصدير عند الخروج
   ├─ index.css               # الثيم والألوان والخطوط والحركات
   ├─ types.ts                # أنواع البيانات
   ├─ lib/
   │  ├─ store.tsx            # الحالة، الإجراءات، بيانات تجريبية، الحفظ المحلي، المعادلات
   │  ├─ excel.ts             # توليد Excel والمشاركة والنسخ الاحتياطي
   │  └─ format.ts            # الأرقام والتواريخ والعملات والفترات
   ├─ components/             # الهيدر، التنقل، الشعار، المكوّنات، الرسوم
   └─ screens/                # Inventory / Sales / Debts / Budget
```

## 3. التشغيل محلياً

المتطلبات: **Node.js 20 أو أحدث** (مجرّب على Node 20) + npm.

```bash
npm install
npm run dev        # وضع التطوير على http://localhost:5173
npm run build      # بناء الإنتاج في مجلد dist
npm run preview    # معاينة نسخة الإنتاج
```

نسخة الإنتاج الناتجة هي **ملف واحد** `dist/index.html` (يُضمّن JS/CSS) مع مجلد `public` للأصول، لذلك يمكنك:

```bash
npx vite preview --host 0.0.0.0 --port 4173
```

### التشغيل على أندرويد عبر Termux (حسب الطلب)

```bash
# 1) تحديث الحزم وتثبيت Node و Git
pkg update -y && pkg upgrade -y
pkg install nodejs-lts git -y

# 2) التأكد من الإصدار
node -v      # يجب أن يظهر v20 أو أحدث
npm -v

# 3) جلب المشروع
git clone https://github.com/<USERNAME>/<REPO>.git batta
cd batta

# 4) تثبيت المتطلبات
npm install

# 5) التطوير (افتح المتصفح على العنوان الظاهر)
npm run dev -- --host 0.0.0.0

# 6) بناء نسخة الإنتاج
npm run build
npx vite preview --host 0.0.0.0 --port 4173
```

> نصيحة Termux: لتشغيل الخادم في الخلفية استخدم `nohup npm run dev -- --host 0.0.0.0 > batta.log 2>&1 &`، ثم افتح `http://localhost:5173` في متصفح الجهاز.

### تثبيت التطبيق على الشاشة الرئيسية (أندرويد)

بعد تشغيل الخادم أو رفع نسخة `dist` على استضافة ثابتة:

1. افتح الرابط في Chrome.
2. القائمة ⋮ ← **إضافة إلى الشاشة الرئيسية**.
3. سيظهر شعار البطة كأيقونة مع شاشة بداية وواجهة RTL كاملة.

## 5. دليل الاستخدام المختصر

1. **سعر الصرف:** أعلى الشاشة، أدخل سعر الدولار بالليرة ثم «تحديث». تُحدَّث أسعار الليرة في الجرد والديون والمصاريف والميزانية مباشرة. (مثال: 1.2$ × 14,200 = 17,040 ل.س، وعند 14,800 تصبح 17,760).
2. **الجرد:** «إضافة صنف» → الاسم، التصنيف، الكمية، سعر الشراء/البيع بالدولار. البحث فوري بالاسم أو التصنيف، والكمية تُعدَّل بزرّي + / − أو من زر التعديل. التصنيفات تُدار من الإعدادات.
3. **المعاملات:** «عملية بيع جديدة» → اختر الصنف والكمية واسم الزبون (اختياري). تُخصم الكمية من الجرد فوراً، ويُحسب الربح تلقائياً. زر «تراجع» يعيد الكمية.
4. **الديون:** أضف الدين وحدّد نوعه **له** (مستحق لنا) أو **عليه** (مستحق علينا). «تم السداد» يغيّر الحالة، والديون غير المسددة فقط تدخل في صافي الربح النهائي.
5. **الميزانية:** اختر الفترة (اليوم / الأسبوع / الشهر / الكل). راقب البطاقات والرسم البياني، وأضف المصاريف (إيجار، كهرباء، رواتب…) والإيرادات المتنوعة. يدعم الإدخال بالدولار أو الليرة.
6. **Excel:** زر «تصدير Excel» أو «تنزيل نسخة الآن» أو زر المشاركة. التصدير التلقائي عند الخروج مُفعّل افتراضياً من الإعدادات (قد يطلبه المتصفح للسماح بالتنزيل).
7. **النسخ الاحتياطي:** الإعدادات ← «تنزيل نسخة» (JSON) و«استيراد نسخة» للاستعادة على جهاز آخر.

### المشاركة عبر واتساب / إيميل

- على أندرويد وChrome: زر المشاركة يفتح ورقة المشاركة مباشرة مع ملف `.xls`.
- إن لم يدعم المتصفح مشاركة الملفات: يُنزَّل الملف ثم تشاركه من تطبيق الملفات أو واتساب.

## 7. المعادلات المعتمدة

```text
قيمة البضاعة الحالية = Σ (الكمية × سعر الشراء)
إجمالي المبيعات     = Σ (الكمية المباعة × سعر البيع)
تكلفة المباع        = Σ (الكمية المباعة × سعر الشراء للصنف)
الربح الإجمالي      = إجمالي المبيعات − تكلفة المباع
إجمالي المصاريف     = Σ المصاريف محوّلة إلى الدولار بسعر الصرف الحالي
صافي الربح قبل الديون = الربح الإجمالي − المصاريف + الإيرادات الأخرى
صافي الربح النهائي  = صافي الربح قبل الديون + (ديون له − ديون عليه)
```

- تُختزن المبالغ الأساسية بالدولار، وتُحسب قيم الليرة لحظياً: `القيمة بالليرة = المبلغ بالدولار × سعر الصرف`.
- المصاريف والإيرادات تُخزَّن بعملتها الأصلية، وتُحوَّل عند العرض والحساب حسب سعر الصرف الحالي.
- عند تغيير سعر الصرف لا تتغيّر أسعار الدولار الأصلية—بل تتبدّل فقط القيم المعروضة بالليرة، كما هو مطلوب.

## 8. الخصوصية والبيانات

- لا توجد خوادم ولا تحليلات ولا حسابات مستخدمين.
- لا أذونات كاميرا أو موقع.
- كل البيانات في متجر المتصفح المحلي على جهازك.
- مسح بيانات المتصفح أو استخدام وضع التصفح الخاص قد يحذف البيانات؛ لذلك صدّر نسخة Excel أو JSON بانتظام.
- لجلب بيانات جهاز سابق استخدم «استيراد نسخة» من ملف JSON الاحتياطي.

> **ملاحظة تقنية مهمة:** نسخة هذا المستودع نسخة ويب/PWA تعتمد على `localStorage`. متطلبات SQLite الأصلية تخص التغليف الأصلي لأندرويد (Native/WebView). عند التغليف يمكن استبدال طبقة التخزين في `src/lib/store.tsx` بسهولة بمشغل SQLite (مثل `@capacitor-community/sqlite`) مع الحفاظ على نفس الواجهة والإجراءات.

## 9. التغليف كتطبيق أندرويد (اختياري)

هذه النسخة قابلة للتغليف كتطبيق أندرويد عبر Capacitor، لكن **بناء APK يتطلب Android SDK/Gradle**، وهي أدوات لا تتوفر افتراضياً داخل Termux ولا تُبنى في بيئة هذه النسخة. الطريقة القياسية:

```bash
npm install @capacitor/core @capacitor/cli @capacitor/android
npx cap init "بطة" com.yam.batta --web-dir=dist
npm run build
npx cap add android
npx cap sync android
cd android
./gradlew assembleDebug    # ينتج ملف APK للتجربة
```

اضبط في `android/variables.gradle`:

```gradle
minSdkVersion = 23        // Android 6.0
compileSdkVersion = 35
targetSdkVersion = 35
```

- الأذونات المطلوبة: **تخزين/مشاركة الملفات فقط** (لا كاميرا، لا موقع). على Android 10+ يُفضّل الاعتماد على مشاركة الملفات ونظام التخزين المحصور.
- للبناء الاحترافي في السحابة يمكن استخدام GitHub Actions مع Android SDK، ثم تنزيل الـ APK من مخرجات الـ workflow.
- ملفات المشروع كاملة وقابلة للتشغيل مباشرة عبر `npm run build`، ولا تحتاج أي ملفات إضافية غير موجودة.

## 10. قائمة اختبار موصى بها قبل كل إصدار

- [ ] فتح التبويبات الأربعة والتأكد من عمل البحث والتصفية.
- [ ] إضافة صنف ثم تعديله ثم حذفه.
- [ ] بيع كمية: التأكد من خصم الجرد، صحة الإجمالي $ و ل.س، وربح العملية.
- [ ] التراجع عن البيع: رجوع الكمية وحذف العملية من السجل.
- [ ] تغيير سعر الصرف: تحديث كل القيم في الجرد والديون والمصاريف والميزانية.
- [ ] إضافة دين «له» وآخر «عليه» ثم السداد والتأكد من الصافي.
- [ ] إضافة مصروف بالدولار وآخر بالليرة وإيراد متنوع: التأكد من ظهورها في الفترة الصحيحة.
- [ ] التحقق من تحديث `صافي الربح النهائي` بعد كل عملية.
- [ ] تصدير Excel: فتح الملف والتأكد من الأوراق الخمس واتجاه RTL والإجماليات.
- [ ] مشاركة الملف عبر واتساب/إيميل (على جهاز حقيقي).
- [ ] النسخ الاحتياطي JSON ثم استيراده بعد مسح البيانات.
- [ ] الوضع الليلي، التخطيط على شاشة صغيرة، وشاشة البداية.
- [ ] التصدير التلقائي عند الخروج (فعّله من الإعدادات أولاً).
- [ ] تشغيل على إصدارين من أندرويد على الأقل عند التغليف الأصلي (6.0 وحديث).

تم التحقق في هذه النسخة من: نجاح بناء الإنتاج (`vite build`)، وخلو أنواع TypeScript من الأخطاء، وترابط منطق الحسابات والتصدير في الكود. اختبار الأجهزة الفعلية وبناء APK يبقيان خطوة تسليم منفصلة تتطلب بيئة أندرويد.
